System Overview

How IDEAgent Fits Together

IDEAgent is a small stack of focused, self-hosted components. Each one does a single job well, and they connect over clean protocols — WebSocket, MCP and REST — so you can run the whole thing on your own machine or your own servers, with your own model keys.

The stack, top to bottom

A request flows down this stack and the results stream back up:

01PyCharm IDEAgent plugin — the tool window in your IDE (Chat · Threads · Tasks · Edits), human-in-the-loop, local voice.
↕  WebSocket — hello / user_message / resume / goodbye, streamed events
02LangAgent gateway — FastAPI + LangGraph deep agent. Runs the turn, enforces HITL, redacts secrets, coordinates peers (ACP), calls your model provider.
↕  MCP (HTTP / SSE)  ·  ↕ your AI provider (OpenAI · Anthropic · Ollama)
03MCP server + context engine — find_symbol / get_context / sync_rag over an indexed model of your project.
↕  REST (port 5810)
04RAG server — ChromaDB + local embeddings; stores code, learnings, snapshots and docs.
↕  /upload re-index
05File watcher plugin — watches your files per machine and keeps the RAG index fresh.

A request, end to end

1
You ask
You type in the plugin; it sends a user_message to the gateway.
2
Agent gathers context
The gateway's agent calls the MCP context engine, which retrieves the right code from the RAG.
3
Agent acts
It plans, calls tools, and proposes or makes edits — pausing for your approval if HITL is on.
4
Index updates
record_change triggers the file watcher to re-index, so the next request sees the change.

Why it's built this way

  • Separation of concerns. The IDE plugin does UI; the gateway does reasoning; the MCP/RAG does memory. Each can evolve — or be replaced — without touching the others.
  • Privacy by construction. Embeddings and retrieval are local, your keys live only on the gateway, and only the context window you assemble is ever sent to a provider. With Ollama, nothing leaves your machine.
  • You stay in control. Per-thread human-in-the-loop, plus optional redaction of secrets from tool output, mean the agent never acts — or leaks — behind your back.
  • Scales across machines. Threads route by id on a single hub, and file watchers register themselves, so multiple agents and hosts coordinate cleanly (including cross-project ACP).

Deployment

The three backend services — gateway, agent and RAG — ship as containers and come up together with Docker Compose on an internal network. The two IDE-side pieces, the IDEAgent plugin and the file watcher, install into PyCharm / IntelliJ. Point the plugin at your gateway URL and you're running.
