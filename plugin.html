The PyCharm IDEAgent Plugin

The plugin is the face of the whole system — a native PyCharm / IntelliJ tool window that turns your IDE into a full agentic coding surface. It does not talk to any LLM itself: it connects to your own LangGraph gateway over a WebSocket, streams the agent's reasoning and edits back into the editor, and keeps you in control with a per-thread human-in-the-loop switch.

What it does in your IDE

IDEAgent installs as a tool window with four tabs, styled after modern agentic assistants but running entirely against infrastructure you own:

  • Chat — project-aware conversation with the agent. Responses stream token-by-token as the gateway produces them, with a live title generated for each thread.
  • Threads — every conversation is a persistent thread. You can start a new thread, switch between them, and resume an earlier one; the gateway keeps the state so history survives restarts.
  • Tasks — the agent's planned steps for a request, so you can see what it intends to do before it does it.
  • Edits — the concrete file changes the agent proposes or applies, surfaced inside the IDE rather than buried in chat text.

Human-in-the-loop (Auto toggle)

Each thread carries an Auto switch that turns human-in-the-loop (HITL) on or off. With HITL enabled, the gateway pauses before consequential tool actions and the plugin shows an approval prompt in the tool window; you approve or reject, and only then does the agent continue. With Auto on, the agent proceeds without asking.

You are always the gate. The HITL preference travels with the thread and is re-sent to the gateway on every relevant frame, so a resumed or reconnected thread keeps the exact approval behaviour you chose.

How it connects to the gateway

The plugin speaks a small WebSocket frame protocol to the gateway. Identity and preferences ride along so the gateway always knows who is asking and how to behave:

FRAME 1
hello
Opens the connection and sends stable machine identity (machine_id, OS, arch, hostname) plus per-thread config.
FRAME 2
user_message
Your prompt. The gateway runs a turn and streams events back.
FRAME 3
resume
Your HITL decision (approve / reject), which lets a paused turn continue.
FRAME 4
goodbye
Cleanly closes the thread connection.

Live preferences — the Auto (HITL) switch and tools-result redaction — are attached to the hello, user_message, resume and goodbye frames, so a change takes effect immediately without reconnecting. The machine identity is sent once in hello (it is stable per connection) and is what enables multi-machine coordination between agents.

MCP tools & settings

Through the gateway, the agent can use MCP tools — the context engine, RAG search, project memory and more. The plugin's Settings page lets you configure this without editing files:

  • Gateway URL — where your LangGraph gateway is reachable, plus a one-click Test connection.
  • MCP Servers — a dedicated sub-page to add and manage the MCP servers the agent may call.
  • Default Auto — the starting HITL mode for new threads.
  • Editor behaviour — auto-open edited files and auto-close editor tabs on a new thread.
  • Tools results & terminal redacted — strip secrets (IPs, emails, credentials) from tool output before it is shown or sent onward.

Local voice

IDEAgent ships optional, fully local voice: Piper for text-to-speech and whisper.cpp for speech-to-text. You can talk to the agent and hear its replies without any cloud speech service — the audio never leaves your machine.

Privacy & trust — what you should know

The plugin is powerful because you trust your own gateway. Driven by the gateway, the agent can execute shell commands on your machine and read/write your project files. It also sends code and context to the gateway over the WebSocket, which then calls the AI provider you configured with your keys. Everything runs on infrastructure you own — but the plugin is only as safe as the gateway you point it at. Optional tool-output redaction reduces the risk of leaking secrets in tool results.
