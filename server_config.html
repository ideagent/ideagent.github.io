IDEAgent is privacy-first by construction: with Ollama as the model host, no code, no prompt and no key ever leaves your infrastructure. But running a flagship coding model fully local is real GPU work — it needs serious, correctly-built hardware. So we're building it for you. The IDEAgent Enterprise Node is planned in two matched configurations: a 4-GPU flagship with 192 GB of aggregate VRAM, designed to host 70B–80B-class models at native BF16 precision while retaining memory headroom for inference, context and KV cache; and a 2-GPU tier with 96 GB of aggregate VRAM, comfortably targeting 32B-class models at native BF16 precision as well as larger models using optimized quantization. Both are pre-configured, turnkey server appliances engineered to run the whole IDEAgent stack — gateway, RAG embeddings and a local Ollama model — completely offline, out of the box. You won't be handed software and wished luck: you get the machine, assembled, validated and ready to serve your developers.

Why we build the box, not just the software

Fully-local AI is only as private as the machine it runs on — and only as fast as that machine is correctly specced. The difference between "Ollama technically runs" and "Ollama serves a whole engineering team without stalling" is in the hardware: VRAM to hold the model, PCIe lanes to feed the GPUs, system memory bandwidth to support model loading and inference workloads, and redundant power to stay up. Getting that wrong is expensive and slow to diagnose. We remove that risk by delivering a single, validated appliance so your fully-local IDEAgent deployment works on day one.

Where it started: a single RTX 3060

We are not guessing at these requirements. IDEAgent's RAG software was developed and runs today on a deliberately modest workstation — a single NVIDIA GeForce RTX 3060 on an AMD Ryzen 5 2600X six-core CPU, under Ubuntu 24.04.4 LTS (x86_64), hosting both an Ollama instance and a Docker stack. That box is proof the software is honest about its footprint: the framework itself runs on hardware many teams already own.

But that same experience is exactly why the appliance exists. A single RTX 3060 is fine for developing and running the RAG, embedding and supporting services — it is not enough VRAM to serve large coding models to a whole team fully offline. Moving to large native-precision models is where correctly-built hardware matters: sufficient VRAM, PCIe connectivity, memory bandwidth, cooling and redundant power that a normal development workstation simply does not provide.

Model capacity — native precision and quantized deployment

Model memory requirements depend on architecture, precision, context length, KV-cache configuration, inference engine and concurrency. For dense models, BF16 weights require approximately two bytes per parameter before runtime overhead. IDEAgent therefore specifies its nodes by usable model class rather than tying the appliance permanently to one model release.

Deployment Approx. BF16 weight memory 96 GB Team Node 192 GB Enterprise Node
32B-class model ~64 GB ✓ Native BF16 with substantial headroom ✓ Native BF16 with extensive headroom
50B-class model ~100 GB Quantization required for full GPU residency ✓ Native BF16
70B-class model ~140 GB Quantization required ✓ Native BF16 with remaining VRAM for runtime and context
80B-class model ~160 GB Quantization required ✓ Native BF16, workload and context dependent
Very-large / 100B+ models Architecture dependent Optimized quantization Optimized quantization or offload

IDEAgent's context engine is designed to retrieve the code and project knowledge relevant to the current task rather than repeatedly loading an entire repository into the model context. Context length and KV-cache allocation can therefore be tuned to the actual development workload, preserving VRAM for model weights and concurrent inference.

⚠️ Physical deployment constraints

Before you site the appliance, plan for two hard requirements:

  • 230V deployment. The flagship configuration is designed for a dedicated 200V–240V AC server-room power circuit. Final electrical requirements will be validated as part of the production specification before units ship.
  • Server-room acoustics. This is a dense multi-GPU server, not a desktop workstation. High-static-pressure fans are required to maintain airflow through the GPU array under sustained load. The appliance should therefore be installed in a rack, dedicated IT room or datacenter environment rather than beside developers' desks.

🎯 Why the appliance makes sense for your team

If you run engineering at a software company, these are the pressures it takes off you:

  • Zero-egress deployment. When IDEAgent is configured exclusively with local models, source code, prompts, retrieved context and model inference remain inside infrastructure controlled by your organization. This makes the appliance suitable for environments where external AI processing is prohibited or undesirable, subject to your organization's own contractual, regulatory and security requirements.
  • Predictable infrastructure costs. Local inference converts variable model-API or rented-GPU consumption into an owned infrastructure model. For teams running frequent agent operations, repository analysis and automated workflows, that makes capacity and cost easier to plan.
  • Local model performance. The model sits inside your infrastructure with no Internet round trip between IDEAgent and the inference server. Performance is determined by the selected model, precision, context size, concurrency and hardware configuration rather than an external API's network conditions or rate limits.
  • Model freedom. IDEAgent is not tied to one local model generation. Native-precision models can be selected according to available VRAM, while quantization provides access to much larger model classes when that trade-off makes sense for the workload.

You get two entry points. The 2-GPU node at €32,175 provides 96 GB aggregate VRAM for teams that want strong native-precision local models with access to larger quantized models. The 4-GPU flagship at €53,287 doubles that capacity to 192 GB, bringing 70B–80B-class native BF16 models into practical reach while retaining the option to deploy substantially larger quantized models. Both configurations use the same underlying platform, allowing a Team Node to grow into the four-GPU configuration without replacing the entire appliance.
