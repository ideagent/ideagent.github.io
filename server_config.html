IDEAgent is privacy-first by construction: with Ollama as the model host, no code, no prompt and no key ever leaves your infrastructure. But running a flagship coding model fully local is real GPU work — it needs serious, correctly-built hardware. So we're building it for you. The IDEAgent Enterprise Node is planned in two matched configurations — a 4-GPU flagship running Qwen3.5-397B-A17B, an open-weight mixture-of-experts model (397B total parameters, 17B active), unquantized; and a 2-GPU tier running quantized models for mid-market teams. Both are pre-configured, turnkey server appliances engineered to run the whole IDEAgent stack — gateway, RAG embeddings and a local Ollama model — completely offline, out of the box. You won't be handed software and wished luck: you get the machine, assembled, validated and ready to serve your developers.

Why we build the box, not just the software

Fully-local AI is only as private as the machine it runs on — and only as fast as that machine is correctly specced. The difference between "Ollama technically runs" and "Ollama serves a whole engineering team without stalling" is entirely in the hardware: VRAM to hold the model, PCIe lanes to feed the GPUs, memory channels to load massive contexts, redundant power to stay up. Getting that wrong is expensive and slow to diagnose. We remove that risk by delivering a single, validated appliance so your fully-local IDEAgent deployment works on day one.

Where it started: a single RTX 3060

We are not guessing at these requirements. IDEAgent's RAG software was developed and runs today on a deliberately modest workstation — a single NVIDIA GeForce RTX 3060 on an AMD Ryzen 5 2600X six-core CPU, under Ubuntu 24.04.4 LTS (x86_64), hosting both an Ollama instance and a Docker stack. That box is proof the software is honest about its footprint: the framework itself runs on hardware most teams already own.

But that same experience is exactly why the appliance exists. A single RTX 3060 is fine for developing and running the RAG and embedding side — it is not enough VRAM to serve a flagship coding model to a whole team fully offline. Going to real, unquantized offline mode is where you need the correctly-built hardware below: the VRAM, the PCIe lanes and the redundant power that a development workstation simply does not have.

⚠️ Physical deployment constraints

Before you site the appliance, plan for two hard requirements:

  • Strict 230V requirement. The factory-installed Supermicro 2000W PWS-2K04A-1R power supplies must be fed with a high-voltage 200V–240V AC power line. If the system is plugged into a standard low-voltage 110V office wall outlet, the modules automatically safety-throttle themselves down to 1000W output, which will cause the server to crash under heavy multi-GPU compute loads.
  • Acoustic server-room isolation. Because the graphics cards are packed tightly together with zero gaps, the internal high-pressure Delta fans run at high RPMs. This creates a noise signature of 65dB to 72dB under load. This box cannot sit on an office desk — plan to deploy it in an isolated datacenter server rack or a dedicated IT room.

🎯 Why the appliance makes sense for your team

If you run engineering at a software company, these are the pressures it takes off you:

  • No "cloud egress" security tax. If you build products for regulated end-clients — banks, healthcare systems, insurance platforms — a developer leaking a client's proprietary database schema or system architecture into a cloud AI model can put you in breach of your customer SLAs. Running fully local removes that liability entirely.
  • Predictable R&D overhead. Cloud API costs scale aggressively with usage. The moment your team starts running high-frequency automated multi-agent testing loops or massive local repo searches, cloud token bills can spike without warning. The appliance locks your AI infrastructure cost to a flat, predictable curve.
  • Developer speed and retention. Your senior engineers won't tolerate slow tools. Running a heavy open-weights model locally across an octa-channel DDR5 Threadripper platform keeps token-generation latency near-zero, so the experience feels cleaner than a rate-limited cloud endpoint.

You get two entry points. The 2-GPU node at €32,175 is a budget-friendly starting point for a mid-market team, and the 4-GPU flagship at €53,287 is a cost-saving alternative to private cloud instance hosting for a larger development operation — with a chassis and platform that let you upgrade from two GPUs to four without swapping the box.
